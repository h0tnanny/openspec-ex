## 1. Цели и мотивация

В реальных проектах разработчикам часто требуется адаптировать рабочие процессы, навыки, шаблоны артефактов и правила субагентов OpenSpec под стандарты команды (например, внедрение строгого TDD, проверок безопасности по OWASP, обязательного моделирования баз данных или особых форматов коммитов). Однако ручное редактирование файлов в каталогах `.agent/`, `.cursor/`, `.claude/` сопряжено с рисками: случайное повреждение YAML-метаданных, потеря контрактов OpenSpec и отсутствие простого способа отката к стабильному состоянию.

Данное предложение решает эти проблемы через три ключевых компонента:
1. **Интеллектуальный рабочий процесс `/openspec-edit` (`/opsx-edit`)**: позволяет разработчику редактировать существующие команды или создавать новые на естественном языке. ИИ автономно определяет затронутые файлы среди всех поддерживаемых ассистентов, оценивает матрицу рисков и запрашивает подтверждение при критических изменениях.
2. **Детерминированный (не зависящий от ИИ) CLI-движок бекапа и восстановления**: автоматически создает атомарный снимок всех конфигураций с хешами SHA-256 перед любым изменением, предоставляет откат в одну команду (`openspec-ex restore --latest` или `--id <id>`) и гарантирует мгновенный сброс к чистому эталону (`openspec-ex restore --factory-reset`).
3. **Экосистема пресетов (Presets Ecosystem)**: позволяет сохранять настроенные наборы команд и шаблонов в пресеты (`openspec-ex preset save`), делиться ими с коллегами и мгновенно инициализировать новые проекты одной командой (`openspec-ex init --preset <имя>`).

## 2. Область действия и возможности

### Добавляемые возможности

- **`command-customizer` (Маршрутизатор намерений ИИ и синхронизация агентов)**:
  - Автономный семантический разбор запроса на естественном языке с сопоставлением с файлами `.agent/skills/`, `.agent/workflows/`, `.cursor/rules/`, `openspec/templates/` и `config.yaml`.
  - Матрица классификации рисков (Критический / Предупреждение / Информационный) с интерактивным диалогом подтверждения.
  - Автоматическая валидация YAML-заголовков и синтаксиса Markdown после записи с автооткатом при ошибках.

- **`deterministic-backup-engine` (Ядро CLI для бекапа и отката)**:
  - `npx openspec-ex backup create [--tag <имя>]`: создание неизменяемого снимка активных скиллов, воркфлоу, шаблонов и правил с проверкой контрольных сумм SHA-256.
  - `npx openspec-ex backup list`: список всех исторических снимков с метаданными и временными метками.
  - `npx openspec-ex backup diff <id>`: просмотр различий между текущим состоянием и снимком.
  - `npx openspec-ex restore [--latest | --id <id> | --factory-reset]`: детерминированный откат файлов чистым кодом Node.js без участия языковых моделей.
  - Встроенный в npm-пакет эталонный фабричный снимок для гарантированного возврата к заводским настройкам.

- **`preset-ecosystem` (Управление пресетами команд)**:
  - `npx openspec-ex preset save <имя> [--global] [--desc <текст>]`: сохранение текущей рабочей конфигурации в переиспользуемый локальный или глобальный пресет.
  - `npx openspec-ex preset apply <имя>`: применение пресета к текущему проекту с автоматическим созданием снимка безопасности.
  - `npx openspec-ex preset list`: отображение всех доступных пресетов (проектных, пользовательских и заводских).
  - `npx openspec-ex preset export/import`: экспорт и импорт пресетов в виде переносимых JSON-пакетов.
  - `npx openspec-ex init --preset <имя>`: инициализация нового репозитория сразу с готовым пресетом.

## 3. Аудит соответствия требованиям SSOT (Self-Audit)

- [x] **Сохранены исходные требования пользователя**: редактирование команд на естественном языке, 100% командный бекап/откат без ИИ, поддержка пресетов и эталонный factory-reset.
- [x] **Исключены ошибки и галлюцинации LLM при бекапе**: файловые операции выполняются исключительно модулями Node.js с контролем SHA-256.
- [x] **Мультиагентный паритет**: изменения синхронизируются для всех 23+ поддерживаемых ИИ-ассистентов (Antigravity, Cursor, Claude Code, Windsurf, Copilot, Cline и др.).
- [x] **Целостность спецификаций**: все требования из `explore.md` полностью отражены в дизайне и задачах.
